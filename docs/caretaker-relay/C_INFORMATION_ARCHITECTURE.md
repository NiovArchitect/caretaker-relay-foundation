# C. Caretaker Relay Information Architecture

## Primary destinations (only four)

| Surface | Role |
| --- | --- |
| **Today** | Landing: needs you, what changed, Relay handled, next |
| **Care** | Living context for active care recipient |
| **Care Circle** | People involved + access |
| **Relay** | Conversation (voice first, text second) |

## Secondary

Profile · Settings · Privacy · Connections

## Contextual

**Needs Attention** — appears when something requires the caregiver; not a fifth nav icon.

## Mobile navigation

Bottom nav: Today | Care | Circle | Relay  
Settings via avatar/profile. Large tap targets. One-handed use.

## Responsive

| Viewport | Layout |
| --- | --- |
| Mobile | Single column, bottom nav, bottom composer |
| Tablet | Two-column contextual |
| Desktop | Constrained center, optional right context, persistent composer |

## Today (5-second test)

Caregiver understands: what needs them, what changed, what Relay handled, what happens next.  
Bottom: “Tell Relay what happened…” + microphone.  
No dashboards, feature cards, or architecture copy.

## Care sections (progressive disclosure)

Today · Routine · Care plan · Appointments · Health & observations · Documents · History  
Header always shows active person (e.g. **Olivia**).

## Relay

Natural conversation. Same care context for voice and text.  
Speak responses when enabled. No command language required.

## Handoff (signature)

What changed · Still needs attention · Watch · Sources · Start my shift / Review handoff

## First login (minimal)

1. Who do you care for?  
2. Who helps you? (optional)  
3. What would help most today?  
4. Land on Today — value before configuration.

## Explicit non-goals for v1 IA

- Otzar enterprise navigation  
- Admin-first agency console as default  
- Eight-icon nav  
- Color-only safety states
